# Устройство магазина

Посетитель может посмотреть шесть товаров и их варианты. Регистрация создаёт аккаунт и сразу открывает сессию. Вход по email и паролю восстанавливает личную корзину и историю заказов. Вход доступен на странице аккаунта и из карточки товара.

## Хранение данных

| Данные | Место хранения | Кто может использовать |
| --- | --- | --- |
| Каталог | server/products.json | Все посетители, сервер для расчёта цен |
| Имя, email и хеш пароля | Таблица auth_user | Django устанавливает личность при входе |
| Серверная сессия | django_session | Браузер передаёт непрозрачный идентификатор в HttpOnly cookie |
| Товар, вариант и количество | server_cartitem | Подтверждённый владелец строки |
| Контакты, доставка, товары с ценами, сумма, статус | server_order | Подтверждённый владелец заказа |

Все персональные таблицы находятся в SQLite. Для корзины комбинация владельца, кода товара и варианта уникальна. Представления определяют владельца через request.user, который устанавливает Django по сессии. При запросах на изменение проверяются токен CSRF и актуальность аккаунта открытой вкладки.

## Как страница получает данные

При переходе на `/product/volt/` Django находит маршрут в `server/urls.py`. Функция `product` в `server/pages.py` находит гитару в каталоге и передаёт её в `product.html`. Браузер получает готовую страницу с фотографией, ценой и вариантами.

Кнопка «Добавить в корзину» отправляет обычную HTML-форму методом POST на `/cart/`. Обработчик `cart` передаёт текущего пользователя и выбранный вариант в `adjust_cart`. Django ORM записывает количество в SQLite. Затем браузер по перенаправлению открывает актуальную корзину методом GET.

При оформлении заказа Django подписывает текущий состав корзины и способ доставки. Сервер проверяет подпись и повторно рассчитывает итог по ценам каталога. Создание заказа и очистка позиций владельца происходят внутри одной транзакции.

## HTTP API для программных клиентов

| Запрос | Результат |
| --- | --- |
| GET /api/session | Текущий аккаунт, его корзина и токен CSRF |
| POST /api/auth/register | Проверка данных, хеширование пароля, создание пользователя и вход |
| POST /api/auth/login, POST /api/auth/logout | Начать или завершить сессию |
| POST /api/cart | Прибавить или убрать количество выбранного варианта для текущего пользователя |
| POST /api/orders | Проверить контакты и корзину, пересчитать сумму, создать заказ и очистить корзину одной транзакцией |
| GET /api/orders | Личная история |
| GET /api/orders/:id | Квитанция для владельца |
| POST /api/orders/:id/pay-demo | Подтвердить учебную оплату от имени владельца |

Сервер сопоставляет позиции с корзиной в базе. Если другая вкладка успела её изменить, заказ отклоняется до подтверждения актуального состава. Уникальная пара пользователя и ключа запроса защищает от дублирования заказа при повторной отправке. Заказы без аккаунта из предыдущей версии не попадают в личную историю.
